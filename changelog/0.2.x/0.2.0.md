# 0.2.0 — 2026-09-23

## Added

- **`observation_fields`** and **`description`** — the by-id record now relays the observer's own note and filled project field values, alongside the existing search fields ([#21](https://github.com/cyanheads/inaturalist-mcp-server/issues/21)).

## Changed

- **`inaturalist_get_observation`** and the `inaturalist://observations/{id}` resource now cap `identifications`, `comments`, and `observation_fields` to a shared 40-entry budget across the batch — 40 each for one id, 4 each for ten. A heavily discussed record now returns fewer entries than before, disclosed via `_total`/`_shown` counts on every record and a notice naming any cut ([#6](https://github.com/cyanheads/inaturalist-mcp-server/issues/6)).
- **`identifications_count`**'s description now states it tallies identifications currently agreeing or disagreeing with the community taxon (`agreements + disagreements`), not the thread size — that's `identifications_total` ([#18](https://github.com/cyanheads/inaturalist-mcp-server/issues/18)).

## Fixed

- **`inaturalist_get_observation`** batch records now return in the requested order, with a repeated id requested and counted once ([#25](https://github.com/cyanheads/inaturalist-mcp-server/issues/25)).
- **`inaturalist_get_similar_species`** now returns a typed `taxon_rank_too_coarse` error, instead of an untyped upstream error, for a taxon coarser than genus ([#23](https://github.com/cyanheads/inaturalist-mcp-server/issues/23)).
- **`inaturalist_get_taxon`** no longer renders an unselected summary field, including the heading's `common_name`, as absent in `content[]` when a `sections` selection leaves it out ([#17](https://github.com/cyanheads/inaturalist-mcp-server/issues/17)).
